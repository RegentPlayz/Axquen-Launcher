# Security Policy

## Reporting a vulnerability

Please do not publish exploitable vulnerability details in a public issue.
Until a dedicated security address is confirmed, contact the project developer
privately through the official Axquen Discord:

https://discord.gg/StdYxkEXRc

Ask for a private channel or a safe way to provide the report. Do not post
credentials, tokens, private account data, or weaponized proof-of-concept code
in a public channel.

## Include

- A concise description and potential impact.
- Affected Axquen build or distribution, if known.
- Operating system and relevant environment details.
- Reproduction steps that are safe and authorized.
- Logs or screenshots after removing personal data and secrets.
- Any mitigation you have identified.

## Do not include publicly

Passwords, Microsoft session data, access tokens, private keys, personal
identifiers, private user files, or exploit instructions that enable attacks
against other users.

## Maintainer handling

The maintainer should acknowledge the report, assess scope and severity,
coordinate a fix or mitigation where feasible, and agree on disclosure timing
with the reporter. Avoid sharing reporter identity or sensitive evidence
without permission, except where legally required.

## Supported versions

A formal supported-version and security-fix policy has not been published.
**Developer confirmation required.** Until one is announced, include the
exact build identifier in every report and do not assume older builds receive
security updates.
